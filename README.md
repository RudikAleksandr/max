# MAX Chat

Веб-интерфейс для отправки и получения текстовых сообщений в мессенджере
[MAX](https://web.max.ru/) через сервис [GREEN-API](https://green-api.com/max).
Внешний вид повторяет web.max.ru.

Демо: <https://rudikaleksandr.github.io/max/>

## Как проверить

1. В [личном кабинете GREEN-API](https://console.green-api.com/) создайте инстанс для MAX
   и авторизуйте его с телефона — состояние инстанса станет `authorized`.
2. В настройках инстанса включите «Получать уведомления о входящих сообщениях и файлах»,
   а поле `webhookUrl` оставьте пустым: при заполненном адресе очередь уведомлений
   отвечает ошибкой 400.
3. Откройте приложение и войдите по `idInstance` и `apiTokenInstance` из кабинета.
4. Введите номер телефона другого аккаунта MAX и нажмите «Создать чат».
5. Напишите сообщение и оно придет в MAX. Ответ с телефона появится в чате через пару
   секунд.

По желанию в тех же настройках можно включить и другие уведомления. Приложение их понимает:

- «о статусах отправленных сообщений» - галочки «доставлено» и «прочитано» меняются,
  пока чат открыт;
- «о редактированных сообщениях» и «об удаленных сообщениях» - правка и удаление видны
  сразу, а не после перезагрузки;
- «о сообщениях, отправленных через API» - сообщение из другой вкладки или скрипта сразу
  появляется в чате.

## Запуск

Нужен Node.js 24 (версия зафиксирована в `.nvmrc`).

```bash
npm ci
npm run dev        # http://localhost:5173
```

Адрес GREEN-API задает `VITE_GREEN_API_URL` в `.env` — по умолчанию универсальный хост
`https://api.green-api.com`, можно указать хост инстанса из кабинета.

```bash
npm run build      # проверка типов и сборка в dist/ (открывается по адресу /max/)
npm run preview    # собранная версия на http://localhost:4173/max/
npm run lint       # ESLint и Stylelint
npm run typecheck  # проверка типов
npm run format     # Prettier, ESLint и Stylelint с исправлением
```

## Архитектура

Слои приложения идут сверху вниз, нижний слой не знает о верхних:

- `app` — композиция: провайдеры, маршруты, гарды и настройка при старте;
- `pages` — экраны, которые раскладывают части модулей;
- `modules` — `auth` (вход и выход), `chats` (список и новый чат), `messages` (переписка);
- `shared` — все без предметной области: клиент GREEN-API, компоненты, общие функции.

Модуль устроен так же, по слоям:

```
modules/<модуль>/
├── ui/
├── hooks/
├── api/
├── model/
├── lib/
└── index.ts
```

Модули видят друг друга только через `index.ts`: `chats` зависит от `auth`, `messages` —
от `auth` и `chats`. Эти границы проверяет ESLint (`eslint-plugin-boundaries`).

**Данные.** Ответы сервера, которые можно запросить заново (GetChats, GetChatHistory), лежат
только в кеше TanStack Query. То, что клиент узнал сверх них — события очереди, свои
отправки, введенный номер, — хранится в Zustand. Экран собирается чистым слиянием одного
с другим в хуке (`mergeChats`, `mergeMessages`). Поэтому статус, правка или удаление,
пришедшие раньше самого сообщения, не особый случай: они ждут, пока сообщение появится.

**Получение.** Цикл очереди — `useQuery` с `refetchInterval` в `useIncomingMessages`:
ReceiveNotification, запись события в стор, DeleteNotification. Удаление стоит в том же
шаге, потому что без него следующий ReceiveNotification вернет то же уведомление, а новый
шаг TanStack не начнет, пока не закончился текущий. Запись идет раньше удаления: если
вкладку закроют между ними, уведомление придет еще раз, и повтор отбросит дедупликация
по `idMessage`. Очередь опрашивается и в фоновой вкладке.

**Сессия.** `setupApp()` в `main.tsx` подключает клиент GREEN-API к учетным данным
и к сбросу сессии. Вход и выход сами сбрасывают сторы сессии и кеш запросов и обрывают
запросы прошлой сессии, поэтому ее поздний ответ не попадет в следующую. Ответ 401
на любом запросе возвращает на экран входа с причиной.

## Решения и компромиссы

- **Токен в `localStorage`.** Так вход переживает перезагрузку. Cookie с `httpOnly`
  надежнее, но требует своего бэкенда, а задание — ходить в GREEN-API прямо из браузера.
  «Выйти» удаляет данные.
- **Запросы прямо из браузера.** У GREEN-API открыт CORS, прокси не нужен. Токен
  у GREEN-API — часть адреса, а не заголовок, поэтому адрес собирает клиент из данных
  текущей сессии.
- **Статус доставки только растет** (отправляется, отправлено, не отправлено, доставлено,
  прочитано): статусы приходят не по порядку, а история отстает от очереди.
- **Отправки идут по очереди:** иначе два сообщения подряд могли бы встать в очередь MAX
  в обратном порядке.
